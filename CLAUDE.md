# Project context: Unity third-person melee action game

Unity (C#) game built on the **Starter Assets ThirdPersonController** (`CharacterController`-based, **not** Rigidbody) with the new Input System and Cinemachine. Frank (university student) owns the combat/movement scripts; a teammate wrote the lock-on system and the original interact scripts, and another teammate wrote the enemy AI (`EnemyAI`).

Combat scripts live in `Assets/Scripts/Combat` (namespace `StarterAssets.Combat`); interact scripts in `Assets/Scripts/Interact` (global namespace, matching the teammate's originals). `ThirdPersonController` is in namespace `StarterAssets`.

> This file was written from a design conversation, not generated from the code. If something here contradicts the code, trust the code and tell Frank so this file can be corrected.

## Core design rules (follow these when adding or changing anything)

1. **Entity-agnostic components.** Combat/roll/block must work identically for player and AI. They never read input directly; they read `IMeleeCombatInputSource` (`PlayerMeleeCombatInput` for the player, `AIMeleeCombatInput` for enemies, now in `Combat/Enemies/`). Player-only concepts (Interact, lock-on) stay OUT of that interface.
2. **Timing comes from animation events, not hardcoded floats.** Every timed phase has an `AE_` method plus a dev-time safety-timeout fallback that force-advances and logs a warning if the event never fires.
3. **Optional, null-safe sibling references.** Components fetch each other with `GetComponent` in `Awake` and tolerate `null` (e.g. no `StaminaSystem` = no stamina gating).
4. **Single source of truth for "am I locked out".** `ThirdPersonController.ShouldLockMovement()` aggregates hitstun/dead, knockback (`Health.IsBeingKnockedBack`, so stagger-free pushes like blocked hits aren't cancelled by locomotion), attacking, rolling, parrying (`BlockController.IsParrying`), level-complete. Extend that method for new states instead of scattering checks. Gravity must still apply while locked.
5. **Input pulses vs held state.** Attack/Heavy/Roll/LockOn/SwitchTarget are single-frame pulses cleared in `LateUpdate` (so a stray press can never linger through a cooldown). `AIMeleeCombatInput` stamps each request with `Time.frameCount` and clears it in a `LateUpdate` *after* the frame it was raised in, because the AI raises requests from an `Update` whose order relative to `MeleeCombatController` is undefined. Block is a held state polled directly from the `InputAction` every frame (a Send-Messages callback alone got stuck true when the action had a press-only interaction).
6. **Reusable sibling checks:** `MeleeCombatController.IsAttacking`, `RollController.IsRolling` / `IsInvulnerable`, `BlockController.IsBlocking`, `Health.IsHitStunned` / `IsDead` / `IsBeingKnockedBack` / `IsInvulnerable`. Every action starter (attack, roll, block, AI steering) refuses while hitstunned/dead; the combo cooldown alone is shorter than hitstun and is not enough.

## Components

- **MeleeCombatController** - state machine Idle/Windup/Active/Recovery. Won't start an attack while `Health.IsHitStunned`/`IsDead`. `ComboStages[]` (length-agnostic: combo length is just the array size; 1 stage works), heavy attack (standalone, or finisher queued after any non-final light hit, never after the last). One-slot input buffer during Windup/Active/Recovery; after the combo ends (last light hit or any heavy) `ComboCooldownDuration` applies and **no input is buffered across it** (a fresh press is required). Per-stage: trigger name, damage, stamina cost, knockback distance/duration multipliers, `ForwardPushDistance`. Public: `RequestCancelForRoll()`, `ForceCancelAttack()` (resets state + applies cooldown + `ResetTrigger` on all attack triggers), `FaceTarget()` snaps facing at the start of every attack/combo stage: `IMeleeCombatInputSource.TryGetAttackDirection` wins (player = camera forward from `ThirdPersonController.CameraTransform`, in free cam AND lock-on), else `lookAtReference` (AI: `EnemyAI` sets it to the player; `LockBridge` still sets it but is overridden by the camera direction), else current facing. Parry window: `AE_ParryWindowOpen/Close` record open/close `Time.time`, sent in `HitInfo` (`IsParryable` only if the window opened this attack; close is clamped to the hit time). `IsParryWindowOpen` is exposed for AI. `ApplyHitboxDamage` builds one `HitInfo`, hits each `IDamageable` once per swing (HashSet dedupe), and if any result is `Parried` it calls `Health.Stagger(ParriedStaggerSafetyDuration, ParriedAnimationTrigger)` on itself AFTER the loop.
- **RollController** - dash via `CharacterController.Move`, direction is **camera-relative** (same math as `ThirdPersonController.Move`, using `ThirdPersonController.MovementReferenceYaw`: camera yaw in Free mode, yaw toward the target while locked on, so locked-on rolls are target-relative; NOT `transform.forward/right`). Direction is read from `StarterAssetsInputs` directly; that's accepted because AI doesn't roll by design (with no input it rolls forward). Refused while blocking / hitstunned / dead / insufficient stamina; can cancel an attack only inside its roll-cancel window. Stamina is checked (no spend) before cancelling the attack, then spent.
- **BlockController** (`IInvulnerabilitySource`) - drives `IsBlocking` and the **masked "Block" Animator layer's weight** via `SetLayerWeight` (not a bool-driven state inside the layer). Blocking is refused/dropped while hitstunned, dead, attacking or rolling (`CanBlock()`). `ResolveIncomingHit(in HitInfo, out damageThrough)` -> `BlockResolution` (NotBlocked / Parried / Blocked / GuardBroken), called by `Health`:
  - Direction: hit must come from within `BlockArcDegrees` (total frontal arc) of `transform.forward`, using `HitInfo.SourcePosition`. Applies to block AND parry.
  - Parry: `_lastBlockPressTime` = rising edge of the block **input** (only recorded while `CanBlock()`), so a block held through an attack that becomes active later never counts as a press. Parried if press time is within `[ParryWindowOpenTime, ParryWindowCloseTime]`. Tap-parry works (no need to still be holding at the hit). One press = one parry (press time is consumed). Success: `PostParryInvulnerabilityDuration` of invulnerability (design value), the `Parry` trigger, and a one-shot omnidirectional `Health.ApplyKnockback` on every `Health` within `ParryPushRadius` on `ParryPushLayers`.
  - Block: costs `damage * StaminaCostPerDamage` stamina (no `StaminaSystem` or ratio 0 = free). Knockback scaled by `BlockedKnockbackMultiplier`.
  - Guard break: insufficient stamina -> `SpendUpTo` all of it, `damageThrough = damage - spent / ratio`, stagger with `GuardBreakAnimationTrigger`.
  - Parry recovery: if the Animator HAS the `Parry` trigger, `IsParrying` is true from the parry until `AE_ParryEnd` (safety timeout `ParrySafetyDuration`; also cleared by stagger/death). It locks movement (`ShouldLockMovement`), attack and roll starts, and blocking. Without the trigger the parry is instant with no lockout. `AE_ParryEnd`'s placement = how soon the parrier can punish.
- **Health** (`IDamageable`) - `TakeDamage(HitInfo)` returns `HitResult`. Order: dead -> `Ignored`; any `IInvulnerabilitySource` (gathered in `Awake`: roll i-frames, post-parry) -> `Invulnerable`; `BlockController.ResolveIncomingHit` -> `Parried` / `Blocked` / guard break; else plain hit. Plain hit and guard break share `ApplyDamageAndStagger` (damage, knockback, then `Killed` or stagger). `Stagger(safetyDuration, animTrigger)` is the generalized hitstun (sets `IsHitStunned`, `ForceCancelAttack`, `RollController.ForceCancelRoll` (also on death), plays the trigger, falling back to `Hit` if the trigger doesn't exist on the Animator); ends via `AE_HitReactionEnd` / `AE_StaggerEnd`, the duration is only the dev safety timeout. `ApplyKnockback(source, distMul, durMul)` is public; `IsBeingKnockedBack` is exposed. On death it disables the driving scripts, stops any knockback, disables the `CharacterController` (see Gotchas) and raises `Died(killSourcePosition)`.
- **Hit detection: WeaponTrace** - `MeleeCombatController.WeaponTraces[]` (capsule Base->Tip Transforms + world `Radius`: Lillian's sword, enemies' hands); each light stage picks one by `WeaponTraceIndex`, heavy by `HeavyWeaponTraceIndex` (-1 / none assigned = the old `HitboxOffset` sphere on `ApplyHitboxDamage`, which traced attacks ignore). Traced from `AE_AttackActive` to `AE_AttackRecovery` in LateUpdate (after animation), swept between frames in steps of `MaxStepDistance` (plus one final sweep after `AE_AttackRecovery`), mask = `HittableLayers`, triggers ignored. One hit per `IDamageable` per window; `IDamageable` is found with `GetComponentInParent` (limb hurtboxes -> root `Health`); self = `IsChildOf(transform)`. Parry close time = moment of contact. Hurtboxes: enemies = their ragdoll limb colliders (`RagdollController.CollidersAsHurtboxes`, kinematic, on a layer that must NOT collide with CharacterController layers and must be in the player's `HittableLayers`); the player = her CharacterController capsule.
- **Hit feedback** - `HitInfo.HasContact/ContactPoint/ContactDirection`: per target, `WeaponTrace.Sweep` returns `TraceHit`s whose point is the hit collider's closest surface point to the blade capsule of the step that touched it (`Collider.ClosestPoint`, bounds for non-convex meshes), direction = tip motion; sphere hits use the closest point to the sphere centre. `HitInfo.Attacker` = the attacker's character object (no longer `transform.root`). `Health.HitReceived(HitInfo, HitResult)` fires after every resolved hit except Ignored. `HitFeedback` (defender side, needs Health) has per-result slots (Hit, Killed (FX falls back to Hit), Blocked, GuardBroken, Parried, Invulnerable): FX prefab (spawned unparented at the contact, facing the swing, destroyed after `FxLifetime`), hit-stop seconds (`HitStop.Freeze` on defender AND attacker: Animator.speed 0, per character, unscaled time, released on disable; added to the attacker if missing) and camera shake force (`CinemachineImpulseSource` on the same object; cameras need a `CinemachineImpulseListener`). `WeaponTrail` (on the `WeaponTrace` object): world-space ribbon Base->Tip emitted while `WeaponTrace.IsTracing`, Catmull-Rom smoothed (`Subdivisions`), fades over `Lifetime` via `ColorOverAge` vertex colours (material must use vertex colour, e.g. URP Particles/Unlit).
- **RagdollController** (enemies; needs `Health`) - Ragdoll Wizard bodies (auto-found: child Rigidbodies with a Joint + their connected bodies, or the `Bodies` list) are kinematic while alive, colliders ON as hurtboxes (`CollidersAsHurtboxes`, else off). On `Health.Died` (event, carries the killing hit's `SourcePosition`) the death clip plays while bone poses are recorded in LateUpdate; `AE_EnableRagdoll` (safety `RagdollSafetyDelay`; immediate if no `Die` trigger) disables the Animator and makes the bodies dynamic with the velocity the animation gave each bone, plus `KillPushSpeed` away from the killer. Not on the player (camera follows the root, spring bones would need disabling). Corpse isn't frozen; `DestroyDelayAfterDeath` removes it.
- **Limb colliders / ragdoll layers** - `Tools > Physics > Ragdoll Cleanup` (`Assets/Scripts/Editor/RagdollCleanup.cs`): every Rigidbody under the selection (not the root's own) -> chosen layer, optionally kinematic and joints removed; undoable. Plan: Lillian's kinematic limb colliders on a `PlayerLimbs` layer that collides only with `Ragdoll`/`Props` (never her own or enemies' CharacterController layer, never triggers), and excluded from GroundLayers, hitbox, lock-on, interact and camera-collision masks.
- **StaminaSystem** - `TrySpend` (all-or-nothing), `SpendUpTo` (partial, returns amount spent; used by guard break), `HasEnoughStamina`, regen after a delay.
- **ThirdPersonController** - Starter Assets controller, kept intentionally (Frank likes the feel). It is the **sole owner of camera rotation**, including the locked-on branch, and of the camera *reference*: assign `GameplayCamera` (the camera with the CinemachineBrain) in the Inspector; `CameraTransform` exposes it to `RollController` and `LockOnController`. Unassigned falls back to the `MainCamera` tag with a warning.
  - **Movement modes** (`MovementMode` enum, `CurrentMovementMode` resolved at the start of `Move()`): `Free` (camera-relative input, face the move direction, sprint allowed) and `LockedStrafe` (while `LockOnController` has a usable target: input relative to the player->target direction, up = toward, sideways = circle, always faces the target with `StrafeRotationSmoothTime`, speed `StrafeSpeed`, sprint = `StrafeSpeed * StrafeSprintMultiplier`). `_targetRotation` is the move direction in both modes. `MovementReferenceYaw` is the single "what does forward input mean" source (also used by `RollController`).
  - Animator: `Speed`/`MotionSpeed` always set (the Idle/Walk/Run blend is the fallback in every mode). Optional, only set if present: `IsStrafing` (bool), `StrafeX`/`StrafeY` (float, character-local direction, normalized: magnitude 0.5 at `StrafeSpeed` (walk), 1 at `StrafeSpeed * StrafeSprintMultiplier` (sprint), piecewise-linear in between, clamped to 1; damped by `StrafeAnimationDampTime`) and `StrafeBlend` (float 0..1, 1 while locked on, damped by `StrafeBlendDampTime`). Sprint-strafe = `StrafeSpeed * StrafeSprintMultiplier`. The strafe 2D tree should place walk clips at 0.5 and sprint clips at 1.
- **Enemies** (teammate, `Assets/Scripts/Combat/Enemies/`, Spanish comments): `EnemyAI` = NavMeshAgent brain (detect, chase, optional `PatrolRoute` patrol); HOW it attacks is an `EnemyAttackBehavior` subclass on the same object (`MeleeAttackBehavior` -> `AIMeleeCombatInput` + `MeleeCombatController`; `RangedAttackBehavior` -> coroutine windup + `EnemyProjectile`). Range and `TimeBetweenAttacks` live on the behavior (`TryAttack` handles cooldown). Our integration on top of it: (1) facing: `EnemyAttackBehavior.ControlsFacingWhileAttacking` (melee = true) stops `EnemyAI` turning the enemy mid-attack; `MeleeAttackBehavior.Execute` sets `MeleeCombatController.lookAtReference` = player, so facing is a snap at attack start plus `TrackTargetDuringWindup` (enable on the enemy) until `AE_AttackActive`, then the swing is committed. Ranged still turns via `EnemyAI.FaceTarget` (projectiles aim at the target directly). (2) Stops the agent while hitstunned/being knocked back (knockback owns movement). (3) Engagement: registers with the player's `CombatStateTracker` (via `GetComponentInParent` on the located player) while attacking or within `DetectionRadius`; keeps the previous value while staggered; unregisters out of range, with no player, on death (checked before the NavMesh guard, because death disables the agent) and in `OnDisable`. `Enemy.prefab` has BOTH a NavMeshAgent and a CharacterController (knockback/forward push use the controller while the agent is stopped). Known gap: a `RangedAttackBehavior` coroutine is not cancelled by stagger/death, so it can still fire mid-stagger.
- **CombatStateTracker** (player) - `IsInCombat` + `CombatStateChanged` event. In combat while any of: registered engaged enemies (a SET of `UnityEngine.Object`, destroyed entries pruned each frame), `IsAttacking`, `IsRolling`, `LockOnController.IsLockedOn`. Enter immediately; exit after `CombatExitDelay` (2s) with no condition. API for AI: `RegisterEngagedEnemy(this)` / `UnregisterEngagedEnemy(this)` (idempotent).
- **CombatCameraSwitcher** (player) - sets the combat `CinemachineVirtualCameraBase.Priority` (Cinemachine **3.1**, `Unity.Cinemachine`) to `InCombatPriority` (20) / `OutOfCombatPriority` (0) on `CombatStateChanged`; the exploration camera's priority sits between. The CinemachineBrain's blend does the transition. Both cameras follow `CinemachineCameraTarget`, so `ThirdPersonController` still owns rotation (lock-on included).
- **CombatMusicBridge** (player) - calls the teammate's `AdaptiveMusic` singleton (`Assets/Audio/Music`, global namespace, `MusicManager` prefab; mixer snapshots): `Combat()` only while `EngagedEnemyCount > 0` (an enemy chasing/attacking; the player's own attack/roll/lock-on do NOT start the music, unlike `IsInCombat`), `Exploration()` after `ExitDelay` with none; polls `GameManager.levelComplete` and calls `Win()` once (then ignores combat). Null-safe if no MusicManager is in the scene.
- **CombatStanceLayer** (player) - drives the masked upper-body "Combat" Animator layer's weight (single stance state, like the Block layer) from `CombatStateTracker.IsInCombat`. Fades out fast while `ThirdPersonController.ShouldLockMovement()` (now public) is true, otherwise the override layer would replace the upper body of attacks/rolls/hits/parry. Applied weight = stance weight x (1 - Block layer weight), so blocking overrides it regardless of layer order. With a `SwordHolster` the target is `SwordHolster.IsStanceVisible` instead of `IsInCombat` (stays up through Sheath).
- **SwordHolster** (player, `IBlockReadiness`) - re-parents the sword between `BackSocket` / `HandSocket` (keeps its world scale; bones are 100x) and plays states `Unsheath` / `CombatIdle` / `Sheath` on the Combat layer with `CrossFadeInFixedTime` (no triggers/transitions needed in that layer). States Sheathed/Unsheathing/Drawn/Sheathing. Attack start = instant draw (snap + jump to CombatIdle). In combat or `BlockController.IsBlockRequested` = Unsheath; block waits until `AE_UnsheathEnd` (BlockController's `CanBlock` checks every `IBlockReadiness`; the press isn't recorded, so a block from a sheathed sword can't parry). Out of combat and not blocking for `SheathDelay` = Sheath. Any `ShouldLockMovement` action interrupts: sword stays where it is, the missing animation plays afterwards. Re-entering combat mid-Sheath: back to CombatIdle if the blade is still in hand, else Unsheath. Events `AE_SwordToHand`, `AE_UnsheathEnd`, `AE_SwordToBack`, `AE_SheathEnd` (ignored outside their phase; safety timeouts). Dead = left where it is. Placement: component context menu `Sword Placement/Preview In Hand|On Back`, move/rotate the sword, then `Save Sword Placement To Socket` (the socket takes the sword's pose, sword re-zeroed; Undo-able, Edit mode).
- **Lock-on** (teammate): `LockOnController` (target acquisition/validation; view camera = optional serialized override, else `ThirdPersonController.CameraTransform`, resolved in `Start`), `LockBridge` (player-only glue; sets `MeleeCombatController.lookAtReference`, does NOT touch the camera), `ILockable` + `DamageableLockTarget` (global namespace; replaced the old `LockTarget`). Target switching (mouse scroll Y / right stick X; `StarterAssets.inputactions` names the action `SwitchTargets`, so `PlayerMeleeCombatInput` has both `OnSwitchTargets` and `OnSwitchTarget`; `targetSwitchCooldown`): `SwitchTarget` cycles left/right, ordered by yaw around the player from the camera, wrapping. In combat the candidates are `CombatStateTracker.EngagedEnemies` (behind the player too); otherwise targets in range and in view. Candidates must be alive, in `maxLockRange` and line of sight. When the locked target dies, `Update` retargets the candidate closest to the player from the same pool; leaving range / losing sight still drops the lock.
- **SkirtSpringBones** (`Assets/Scripts/SpringBones`, namespace `StarterAssets.SpringBones`, not `...Physics` to avoid shadowing `UnityEngine.Physics`) - Verlet spring chains for Lillian's skirt (`DEF-Skirt_Base.*` chains, found by name if the list is empty, sorted around the body). LateUpdate (execution order 10000): restore rest rotations -> animated targets, carry `1 - MovementInfluence` of the anchor's (DEF-spine) movement/rotation so rolls/knockback don't fling it, integrate (gravity, damping, stiffness curve waist->hem, rates per 1/60 s), constraints (sideways links between neighbouring chains that only resist stretching, then per chain top-down: length + `MaxAngle`, then `SpringBoneCollider.PushOutSegment`: whole segment vs capsule, rotating the segment about its parent; collision runs last and overrides `MaxAngle`, otherwise a raised thigh went through the skirt), then rotate the bones. Optional `LegDrivers` (chain root + thigh + `FollowWeight`): the chain's animated targets rotate about its pinned hinge by the thigh's swing since rest (direction thigh -> first child, measured in hips space so body turn/lean and leg twist don't count; rest captured in Awake = file pose), so the front panels (`DEF-Skirt_Base` over `DEF-thigh.L`, `DEF-Skirt_Base.010` over `DEF-thigh.R`) lift with the leg in the same frame; neighbours follow via the sideways links. `FollowForwardOnly` (default off) drops only the backward part of the swing. Per-driver `Hold` = minimum stiffness along the whole driven chain (otherwise the loose hem kept hanging under gravity and the bottom bones clipped while only the top followed). Collision side: if a point ends up past the capsule axis, it is pushed out on the side of its animated/leg-driven target (when that target is outside the capsule) instead of the nearest side. Sole owner of the skirt bones (not in the Avatar). `SpringBoneCollider` is NOT a Unity Collider (would hit the CharacterController/hitboxes/casts); sizes are world metres and ignore bone scale (the rig has a 100x bone scale). `ResetSimulation()` after teleports (also automatic past `TeleportDistance`).
- **SpringBoneChains** (same folder/namespace) - the simple version for jiggle bones / hair / tails: independent chains from listed roots (no sideways links, no leg drivers, one constraint pass), each hanging from its root's parent (per-chain `MovementInfluence` and teleport reset). Works with a single bone: a chain's last bone gets a virtual tip `TailLength` metres along `TailAxis` unless it ends in a Blender `_end` leaf (Lillian: `DEF-breast.L/R` + `_end`). Stiffness root->tip interpolated. Restores rest rotations every frame, so only for bones the Animator doesn't drive. Reuses `SpringBoneCollider`.
- **Look-at rig** (Animation Rigging): RigBuilder + Animator on `PlayerArmature`, `LookAtRig` (Multi-Aim on `Head_LookAt`, constrained = `DEF-spine.005`, source = `LookAtReference`) lives UNDER the `Lillian` model object (see Gotchas). Aim/Up axes are set for the Rigify head bone (local +X forward, +Y up), not the old Mixamo-style Z. `LookAtRigWeight` (`Assets/Scripts/Rigging`, namespace `StarterAssets`) blends the Rig weight to 0 when the target is more than `MaxAngle` behind her horizontally (hysteresis, `BlendSpeed`), so she looks forward instead of jittering against the aim limits; runs in Update, before the Animator evaluates.
- **Interact**: `IInteractable`, `InteractComponent` (capsule cast from `rayOrigin` along the camera's forward takes priority; fallback is the first entry of the trigger-proximity list, no facing heuristic; camera = `interactionCameraOverride`, else `Camera.main`), `PlayerInteractInput`, `Pickup`.

## Animation conventions

- Attack triggers `Attack1..N`, `HeavyAttack`; `Roll`, `Hit`, `Die` triggers; `IsBlocking` bool. Optional triggers `Parried`, `GuardBreak` (fall back to `Hit` if missing) and `Parry` (skipped if missing), checked with `AnimatorExtensions.HasParameter`. Roll/Hit/Die/Parried/GuardBreak should be **Any State** transitions with **Has Exit Time off** (exit time caused a visible desync before).
- Each attack state's exit-time transition back to locomotion must start AFTER `AE_AttackEnd` (exit time >= its normalized time). The next combo trigger is set inside `AE_AttackEnd`; if the exit transition is already running it can't be interrupted, the state lands in locomotion with the trigger armed and no transition for it, and the next stage times out in every phase.
- Attack clip events: `AE_AttackActive`, `ApplyHitboxDamage` (hit frame), `AE_AttackRecovery`, `AE_AttackEnd`; optional `AE_RollCancelOpen/Close`, `AE_BeginForwardPush(float)` (0 = use the stage's `ForwardPushDistance`), `AE_ParryWindowOpen/Close` (no Open = unparryable attack).
- Roll clip: `AE_IsRolling` (end), `AE_IFrameStart/End`. Hit clip: `AE_HitReactionEnd`. Parried / GuardBreak clips: `AE_StaggerEnd` (alias of `AE_HitReactionEnd`). Parry clip: `AE_ParryEnd` (control returns; may be before the clip end). Parry state is Base Layer, Any State -> Parry (exit time off), Parry -> locomotion with Has Exit Time ON (no conditions) so it returns to idle by itself.
- **One locomotion state for free AND strafe movement.** `Idle Walk Run Blend`'s motion is a parent 1D blend tree on `StrafeBlend` (0 = free Speed tree, 1 = strafe 2D Freeform Directional tree on `StrafeX`/`StrafeY`). Do NOT add a separate Strafe state: every attack-out / return-in transition is wired to this one state and would need duplicating. `Tools > Animator > Merge Strafe State Into Locomotion` (`Assets/Scripts/Editor/MergeStrafeIntoLocomotion.cs`) folds a separate 2D-tree state into it (backs up the controller first).
- Mesh2Motion clips are **Generic** `.anim` files bound to `Skinned Mesh 0/root/mixamorigHips/...` (imported from GLB via a third-party plugin; Mesh2Motion now also exports FBX). `Tools > Animation > Animation Path Remapper` (`Assets/Scripts/Editor/AnimationPathRemapper.cs`, optional `AnimationBoneMap` override asset) rewrites curve paths to another hierarchy by bone identity (manual map -> same name -> humanoid bone via Avatar/Mixamo table -> normalized name). It renames paths only (no retargeting): valid only when target bones share the source's rest orientation. AE_ events and clip settings are preserved.
- For a different rig (the new Mesh2Motion auto-rig: `root/pelvis/spine_01/...`, humanoid Avatar `Assets/Assets/Animations/Player/HumanoidAvatar`) use `Tools > Animation > Humanoid Clip Baker` (`Assets/Scripts/Editor/HumanoidClipBaker.cs`): samples each Generic clip on a hidden copy of its source rig, reads it through the source rig's humanoid Avatar (`HumanPoseHandler`) and writes a Humanoid clip (RootT/RootQ + muscle curves). Can build a source Avatar from Mixamo names (rig's stored pose = rest pose, must be a T-pose). Not baked: IK goal curves (keep Foot IK off), non-humanoid bones. A Generic `.anim` can't be switched to Humanoid by a setting; the curves are different data.
- Simpler route when the same animations are re-downloaded as FBX (Rig: Humanoid): `Tools > Animation > Animation Event Copier` (`Assets/Scripts/Editor/AnimationEventCopier.cs`) copies events from same-named clips in a source folder to a target folder by normalized time. FBX targets are written to `ModelImporter.clipAnimations` (survives reimport); flags clips whose length differs by >5%.
- Lillian (new player model, Rigify `DEF-` bones + skirt/hair bones) is Humanoid with her own Avatar; her clips come from FBX files in `Assets/Assets/Animations/Lillian` (Humanoid, own Avatar). If a Humanoid source file's Avatar was built from a non-T-pose, every retargeted clip inherits the error (wide arms, long stride): `Tools > Animation > Avatar Pose From Clip` (`Assets/Scripts/Editor/AvatarPoseFromClip.cs`) writes a clip's pose (e.g. `Rest_Pose`, sampled on a temporary Generic copy) into `humanDescription.skeleton` and reimports; backs up the .meta to `AvatarPoseBackups/`. Pose Source = External Clip uses a clip from elsewhere (rotations only, the model keeps its bone offsets): a Generic clip is sampled on a Generic copy of the model; a Humanoid clip (e.g. a duplicated `Rest_Pose`) is muscle data, so it is played through a Pose Rig with a correct Avatar (`General Animations.fbx`) with the body forced upright (not the clip's RootQ). The rigs may differ (Mixamo `Idle.fbx` vs Mesh2Motion): bones are matched by Avatar role, and each target bone is turned (parents first) to point at its child the same way as the posed rig, in root space; twist kept except hips/hands (second axis thigh-thigh / index-little). Only humanoid-mapped bones are written (in-between bones keep the file pose). `Tools > Animation > Rename Clips To File Name` / `Set Loop Time On Clips` / `Bake Root Motion Into Pose` (`RenameClipsToFileName.cs`) edit FBX clip import settings in bulk. Root motion is never used (movement is code-driven), so every Humanoid clip needs Bake Into Pose on Rotation/Y/XZ; unbaked, the hips lose their yaw (whole-body twisting) and the step bounce while the Inspector preview (which applies root motion) still looks fine. The Mesh2Motion source rig's root faces backwards: Rotation = Original + offset 180, Y = Original, XZ = Center of Mass. Animator `Apply Root Motion` off. Packs that split an attack from its recovery (`Sword_Regular_A` + `Sword_Regular_A_Rec`, separate takes, so the importer can't join them): `Tools > Animation > Join Clips` (`AnimationClipJoiner.cs`) writes one Humanoid `.anim` (default `<first>_Full`) with the first clip's settings and events; re-running overwrites in place (GUID kept). It also fixes quaternion sign flips (the takes stored RootQ with opposite signs, which played as a one-frame 360 spin); `Tools > Animation > Fix Quaternion Flips` does the same in place on selected `.anim` clips without touching events or other curves. Kept as one clip on purpose: the combo already handles cutting into the next stage during Recovery.
- Lillian's textures (`Assets/Assets/Textures/Lillian/textures`) come with separate `_Alpha` maps, but URP Lit reads alpha only from the Base Map's alpha channel: `Tools > Textures > Pack Alpha Into Albedo` (`TextureAlphaPacker.cs`) saves `<albedo>Alpha.png` (albedo RGB + chosen channel of the alpha map, resized to the albedo; import settings copied from the albedo, Alpha Is Transparency on, optional mip coverage preservation for Alpha Clipping). Originals untouched.
- Rejected on purpose: a Blend Tree driven by a combo-step int (shared playback clock, events firing at partial weight, can't express the heavy-finisher branch).

## Gotchas learned the hard way

- `CharacterController` **is** a `Collider`. Never `enabled = false` it while anything can still call `Move()` (errors). Only exception: `Health.Die` disables it after stopping every caller (driving scripts off, death knockback stopped, `ThirdPersonController.Update` returns early while it's disabled). A new script that calls `Move()` must also stop on death.
- Interface references (`IInteractable`, `ILockable`, ...) don't get Unity's "destroyed == null". Check `is UnityEngine.Object o && o == null` before touching a possibly-destroyed target.
- Don't rely on `Camera.main` (multiple `MainCamera`-tagged cameras resolved to the wrong one); assign the camera explicitly (`ThirdPersonController.GameplayCamera`) and read it from there. Components that read another component's Awake-resolved value must do so in `Start` or lazily, not in their own `Awake`. For raycasts in the over-the-shoulder view, start from a point near the player but aim with the camera's forward.
- Two systems writing the same transform/`Move()` in one frame fight each other (this caused the "roll backwards stays in place" bug and the duplicate camera control). Give each thing one owner.
- Animator triggers can stay armed if not consumed; reset them when cancelling.
- Any State reactions (Hit/Parried/GuardBreak/Die) cut the playing clip, so its end event (`AE_AttackEnd`, `AE_IsRolling`, ...) never fires. Every action with an end event needs a `ForceCancel...` that `Health.Stagger`/`Die` calls; otherwise it runs until its safety timeout (a roll kept moving the character ~1.5s after being hit).
- With a Humanoid Avatar the Animator binds relative to the **Avatar root** (the object the Avatar was created from), not its own GameObject. Lillian's Avatar root is the `Lillian` child of `PlayerArmature`, so Animation Rigging rigs (and any future IK rig) must be children of `Lillian`; as siblings they fail with "Could not resolve ... not a child Transform in the Animator hierarchy". Keep the Animator itself on `PlayerArmature`: animation events (`AE_`) only reach components on the Animator's GameObject.
- `GameManager.Instance` can be null in test scenes; guard it.
- Per-frame input callbacks arrive before `Update`; `LateUpdate` is where pulses are cleared.
- `CharacterController.velocity` reflects only the LAST `Move()` call of the frame (whichever script ran last). `ThirdPersonController.Move` therefore starts from speed 0 on the first frame after a lockout (`_wasMovementLocked`) instead of inheriting knockback/roll/lunge speed and lurching along its facing.

## `IDamageable` (the real interface lives in Frank's project - read it before changing it)

`HitResult TakeDamage(HitInfo hit)`, `Heal(float)`, and it exposes `MaxHealth` and `CurrentHealth` (the latter used by `DamageableLockTarget.IsAlive`). `HitInfo` / `HitResult` live in `Interfaces/HitInfo.cs` (global namespace). `HitInfo`: `Damage`, `SourcePosition`, knockback distance/duration multipliers, `Attacker`, `IsParryable`, `ParryWindowOpenTime/CloseTime`; build it with the constructor (a `default` struct has 0 knockback multipliers). `HitResult`: Ignored, Invulnerable, Hit, Blocked, GuardBroken, Parried, Killed.
